# 字体描边覆盖率合并实验

状态：候选实现；真实 D3D9 像素测试通过，排行榜实机已确认新路径执行，视觉效果待用户评价。默认关闭。

## 目标和范围

保留灰阶字形，改善浅色描边的重叠灰边，支持黑色及蓝色等字心颜色。没有修改 `lfQuality`、
`lfWeight`、字号、字宽、编码转换、字形查找、字形缓存或纹理尺寸。
不会修复原始字体自身的栅格化缺陷，也不会解决 FontScale 超出固定字形格的裁切。
仅接入宽屏补丁；独立字体补丁保持原状。

## 已确认的原生路径

依据已有 `artifacts/Stardom3-runtime-disasm.txt`：

- `0056A950` 在缺字缓存时调用 TextOutA；`0056AAC6` 读取位图蓝色分量，
  随后的复制循环将其重复到纹理各通道。没有在本次重建此缓存。
- `0056ABC0` 是单字绘制函数，thiscall，六个栈参数，`0056B831` 为 `ret 18h`。
- 第五个参数的 `0x200` 标志使绘制次数变为五；`0056ADD9` 的分发表依次
  偏移四个方向，最后一次绘制主体。`font+0x51` 可增加额外阴影。
- Hook 安装校验入口、五次循环设置和返回指令的签名；不匹配不安装。

## 合成方式

传统四次 alpha-over 使重叠覆盖率成为 `1 - ∏(1 - ai)`。
本实现每次计算前面描边的最大覆盖率 `p`，当前覆盖率为 `a`，输出
`max(a - p, 0) / max(1 - p, epsilon)`；在 SRCALPHA/INVSRCALPHA 下，
最终描边覆盖率成为 `max(a0, a1, a2, a3)`。

主体仍使用原字形纹理 alpha 和原顶点 alpha，没有阈值二值化或笔画腐蚀。
RGB 使用文字顶点颜色，使灰阶纹理作为覆盖率遮罩参与合成。
描边颜色不统一、非轴对齐四边形、额外阴影、已有着色器或不支持的
混合/深度/alpha-test 状态会停止应用修正。常规裁切后的矩形可处理。

每次绘制恢复原像素着色器（要求原来为空）及 c0–c8 常量。
编译好的 ps_2_0 字节码随 DLL 嵌入，无运行时编译器依赖。
着色器引用由游戏原字形纹理的 private data 持有，随纹理销毁释放，
不另建字形纹理缓存或全局设备引用。未测量游戏内性能，不宣称帧率收益。

## 使用

在现有 `Stardom3.Widescreen.ini` 的 `[Widescreen]` 下添加：

```ini
FontOutlineUnion=1
DebugMode=0
```

退出游戏再更换候选 DLL、重启。其他字体和字号配置先保持不变以便比较。
设 `FontOutlineUnion=0` 并重启即可回到当前代码基线的原描边路径。
若要恢复之前安装的其他实验版本，请恢复备份 DLL 和完整 INI。
旧实验的 FontQuality、SmallFontQuality、SmallFontWeight 不属于当前代码基线，
本候选版不会解析这些键。
