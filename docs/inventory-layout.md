# 物品栏等比放大

范围：`GUI/Office/ItemList.txt` 的三个分类分页、五行物品列表、滚动/赠送/离开按钮，以及名称、数量和 Memo 说明；同时适配 `ItemTarget.txt` 赠送对象选择浮层。存档、读档不在本次范围内。

## 结构和处理方式

- 页面为直属根节点的 800×600 画布，唯一卡片位于 (200,35)，尺寸 420×542。
- 匹配完整的三个分类按钮、五行列表及滚动/离开列；分类按钮的横坐标不固定，游戏会随选中分类重新排列。
- 初次通过 `ScaleAspectFitSubtree` 缓存并缩放子树。后续移动使用游戏提交的原始坐标，不重播初始分类位置。
- 分类按钮沿用动画入口的原始起点保护，逐帧结果只缩放一次。
- 已发现页面通过缓存维护控件尺寸，不依赖 30 秒维护周期；隐藏时不执行尺寸维护。
- Label 使用已有临时字号/测量适配；Memo 使用已有临时视口、字号和行距适配。保持编码、逻辑换行、物品数据和字形缓存机制不变。

1920×1080 下卡片为约 756×976，缩放比例 1.8；五行起点间距 153。

赠送浮层是独立的 370×90 根，包含 (0,30) 的 363×56 背板、四个 70×80 人物选项和 46×22 赠送图标。`0048933D` 读取物品卡片的当前位置，`00489A10` 再加原始偏移 `(11,81+行号*85)`。卡片已放大，因此必须先减去卡片坐标，仅缩放偏移，最后加回卡片和页面原点，不能再走普通屏幕边缘定位。浮层子控件单独等比缩放，维护刷新不重新居中浮层。

## 验证

自动测试覆盖完整/不完整/循环树识别、存读档排除、分类动态位置、重复缩放、五行间距及 Memo 视口和基线。

游戏回归需检查：首次打开和退出重进、三个分类来回切换、长名称/说明及数量、滚动首尾、按钮悬停与点击位置。不要为布局测试实际消耗、赠送或删除物品。
